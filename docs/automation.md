# 自动化任务

自动化是 uni-api-web 的服务器任务，不依赖浏览器保持打开。新任务默认暂停；调序默认仅生成建议。支持独立的定时降智检测，也可选择在调序前检测 Astra。

## 范围与参数

每个任务绑定一个来源、API key 和模型。调序额外指定端点、流式状态、统计窗口和数据最大年龄。API key 列表只返回脱敏名称与不透明标识。非 Astra 模型忽略降智指标；Astra 只选择降智指标也可以。来源必须采用 fixed_priority 调度，后台用已有的管理员配置读取权限确认。

可设置参与指标、最小样本数（默认成功率 100、缓存 50、首字 50、降智 20）、置信水平（默认 95%）、首字分位数（默认 p50）、每项实际改善门槛（10% 或 100 ms、2/5/5 个百分点）、统计不确定性容差（默认 0）、连续确认（默认 3）、冷却（默认 1800 秒）、单次最多上移步数（默认 1）、降智检测并发（默认 4）、执行间隔。间隔从本次结束开始计算，调度器每 5 秒检查一次。

## 判定

使用当前 API key 的完整实际目录，不从历史事实或字母顺序推测配置。未参与端点、停用、冷却、缺少样本或数据过期的渠道形成屏障，不会被跨过。每次相邻上移都要求双方来源、key、模型、实际模型、端点、流式状态相同。

A 支配 B 必须满足：所有选定指标的观测值不变差；置信区间支持不劣（允许自定义不确定性容差）；至少一个指标的区间改善达到实际门槛。首字使用更低为好，其余更高为好。默认并非要求每个指标都显著改善。可额外要求 A 支配所有更高优先级渠道。零容差是严格模式，100% 与 100% 的有限样本区间仍会重叠，因而可能无法上移；可显式设置容差，但容差不允许更差的观测值。

成功率是已成功/失败的 attempt，排除取消与跳过，使用 Wilson 区间。首字严格读取 response_created_ms，使用所选分位数和基于二项秩正态近似的区间；无法确定尾部界限时不降级为其他延迟。缓存率保持缓存读取 Token / 有缓存统计的输入 Token 的加权口径，用成对的一分钟 Token 总量进行 400 次确定性 bootstrap；不足两个分钟样本拒绝比较。降智概率使用窗口内 candy-21 规则成功完成的检测（包括已确定关联的 sub2api 账号/分组），失败请求不进分母。所用区间是统计估计，不代表未来表现保证；独立性/平稳性和分钟块长度会影响区间可靠性。

原始事实查询单次上限 200000 条，超出时整次跳过并提示缩短窗口，不用截断样本调序。历史采集未追平、扫描过期或查询失败同样跳过。相同计划、配置版本和更新的数据才能累计连续确认。相同事实反复执行不会增加次数。

## 一致性与审计

PostgreSQL 租约和运行超时防止重复领取，运行中每 15 秒续约。配置更新带 revision 防止覆盖；删除是归档，历史可从全部任务审计分页查看。暂停/删除不会开启新检测；正在发送的检测会完成或在检查到配置变化后取消。后台运行时长上限 4 分钟，两个任务可同时执行，各任务检测并发独立设置。

提交顺序前先保存 prepared 审计，持有来源控制锁、任务版本与租约，重新核对目录及控制 revision。只写该 key/model 的 order，保留原 disabled，不删除临时渠道。应用后核对返回规则并调用现有恢复配置保存逻辑。请求结果不明确或恢复配置保存失败时记录 uncertain，阻止重复提交。日志只记录任务标识、阶段与受控错误分类，不包含密钥。

建议可在详情中手动批准，批准时重新查询最新数据和规则。已应用记录可恢复此前规则：只在来源 revision 仍等于该次应用后的 revision 时执行；恢复后暂停任务。后续人工改动会阻止恢复，避免覆盖。当前提供人工恢复，不根据未来业务波动自动回滚。

每次配置变更和运行保留状态、时间、策略、前后顺序、跨越关系、指标样本/置信区间及跳过原因。提交不确定的记录可点击“核对当前配置并暂停任务”；只读取和保存可确认的状态，不会自动重试写入。未创建或启用的任务不发起收费模型请求。
