# 控制台视觉回归

运行 `npm ci` 和 `node scripts/frontend-fixture.mjs`，然后在浏览器打开
`http://127.0.0.1:43971/_audit/session`。这是仅监听本机的合成数据环境。
模拟修改只影响当前进程的内存。不连接生产网关，不执行实际检测、付款、改密或路由发布。

## 截图基线

在 1440×960、768×960、390×844 和 320×780 下检查总览、观测、管理、请求追踪、
余额、价格、自动化与设置。记录长渠道名、相同前缀的 ID、整位金额和时间到秒的画面。
在浅色、深色、浏览器 200% 缩放及手机触控下检查可操作性。表格允许自己横滚，
页面不能被撑宽；主身份、结果和关闭按钮应可定位。以真实画面判断对齐、换行和遮挡。

对来源操作菜单测试快速扫过父项、斜穿相邻项到子菜单、向左翻转后的斜穿、滚动及
调整视口后的锚定。用方向键进出子菜单。两次 Escape 应分别回到父项和原按钮。
在触控设备上用点按进入和退出。没有输入框的操作菜单与含表单的筛选区分开检查。

## 异步反馈

访问 `http://127.0.0.1:43971/_audit/scenario?mode=long` 设置当前浏览器的模拟响应，
然后返回工作区。可换成 `success`、`failure`、`uncertain`，分别模拟成功、
版本冲突和网关未回执。失败的价格接口由客户端显示通用 HTTP 诊断，保留草稿。

在 1440px 和 390px 下分别测试添加渠道、模型检测、余额读取、价格保存、排序应用。
每个操作记录提交前、约 900ms 的待回执阶段、结果后的画面。比较同一滚动位置下
的标题、工具栏、表头和已有行；若列表数据真实变化，比较未变化的字段或行边界。
长错误和操作编号应出现在可滚动详情或固定反馈位置。失败应可查看原诊断，未知
结果不得标记为成功，也不应无条件引导重新提交。检查其他行仍可操作。

重新启动夹具可还原内存状态。单元与交互测试可用 `npm test`，生产构建用
`npm run build`。两者都不能替代上述浏览器检查。
