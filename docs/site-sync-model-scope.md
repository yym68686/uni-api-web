# 站点账号同步的检测范围

「一键同步并检测」同步所有空闲账号的分组、专用测试 key 和模型目录，检测只使用点击时「检测模型设置」的勾选快照，不使用渠道列表的账号、模型或可用性筛选。没有勾选模型时禁止提交。

可用性、Astra 降智、自动指纹、压缩及 Tool use 阶段均受此快照约束；各检测仍遵循原有模型适用条件。未勾选模型的历史结果保留，站点新发现但未勾选的模型仅加入目录。提交后的设置变更仅影响下一批任务。

单账号行内「同步并检测」及重新登录后的同步使用相同的勾选快照，仅同步该账号，不采用列表的模型筛选。新账号接入时可勾选「同步并检测已选模型」；取消勾选则只同步分组、密钥和目录。首次接入的密码、浏览器及双因素验证使用同一个范围快照。显式单模型检测仍直接检测所选模型。

前端通过 `POST /v1/sub2api/accounts/sync-selected` 发送非空 `models` 数组。旧后台未提供此端点时提示服务待更新，不回退到全模型检测。旧 `/accounts/sync` 入口也要求非空模型数组，拒绝缺失或空范围。

单账号通过 `POST /v1/sub2api/accounts/{id}/sync-selected` 发送非空 `models` 数组，旧 `{id}/sync` 同样要求显式范围。两个单账号入口共用批量的模型验证逻辑：缺失、空值、无效模型或超出256项均拒绝入队；重复模型去重。owner隔离及已有任务保护不变。前端成功后仅读取任务进度，保留渠道列表；旧服务返回404时不降级调用旧接口。

首次接入使用 `POST /v1/sub2api/accounts/scoped`，只有显式的非空模型选择才会探测。旧入口缺失范围的请求及尚未认领的旧任务按仅同步处理。不删除未选模型的历史，也不重放发布时已出站但未确认的请求。

范围以 `console_sub_accounts.sync_models` 与任务原子入队。进度按本轮标记统计启用检测的分组 × 已选模型，不是 HTTP 调用计数：例如 29 个启用分组和 2 个模型是 58 项；停测一组则为 56 项。密钥准备、完成组数与模型项分别显示。

分组密钥就绪就可开始探测。New API 先分页核对专用 key，必要时创建，再批量读取缺失密钥（每批最多 100 个）；仅对不支持批量接口的明确响应降级为带节奏的单条读取。密钥读取与模型请求分别处理限流。同步主任务按 `Retry-After` 保存等候时间，无需占住 worker；已完成项不重跑，停止的任务不恢复。未确认是否执行的模型请求、已完成可用性但其后降智探测被限流的项，不会由整批自动重放。

「站点设置 → 检测速率」可以设账号级 RPM 和并发。Sub2API 可读取的上下游额度留约 20% 余量，并叠加控制台硬上限及适用分组上限；New API 普通账号未声明限额时默认 30 RPM / 2 并发，已确认的限流反馈只调低未知 RPM，持续有成功样本时小幅提高。这里限制的是控制台检测请求，不是同账号上的其他业务流量。余额、鉴权及不能确认原因的 429 不写成模型不支持，也不盲目重试。

回归用例覆盖36个已选模型、291个目录模型和21个分组：本次仅入队并统计756个模型/分组检测项，未选模型的历史记录不变、新发现未选模型保持idle。前端即使当前筛选为其他单个模型，也只提交保存的36个勾选项。另有本地HTTP上游夹具验证实际worker的可用性、指纹入队及能力探测均不越过提交范围，不访问真实站点。
