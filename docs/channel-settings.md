# 渠道设置

在渠道观测打开渠道抽屉，点击「渠道设置」。所有页签共用一份草稿；「校验与预览」展示差异、应用前后的 Key/模型范围，以及实际协议构造后的脱敏请求。确认预览后「保存并应用」。

支持原配置渠道和导入渠道：

- 地址、引擎、模型映射及按需读取上游模型列表。
- 多密钥替换、增删、排序及密钥调度/限额。
- 模型超时、条件超时、心跳、冷却和渠道重试。
- 端点/请求类型/条件过滤、请求头、参数覆盖与删除。
- 工具/图片、代理、余额查询和云平台凭据。
- 单渠道 JSON/YAML；未识别字段保持原值。
- 同一来源批量应用、无凭据模板、复制为一个调用 Key 专用渠道。
- 加密操作记录、结果核对和回滚。删除副本后可从原渠道重新复制。

## 配置与安全边界

原始 provider 身份保持不变，单渠道覆盖独立于配置文件。共享 provider 的修改影响引用它的 Key，预览显示变更前后范围；需要 Key 专用配置时使用复制功能。修改上游身份后，站点关联从有效凭据重新核对，已关联的历史检测不会移动到另一个分组。

初始设置响应仅包含密钥引用。在「密钥」页点击「显示密钥」可按需读取并复制真实上游 API key；隐藏、离开页签或关闭弹窗后清除显示值。查看不会改变草稿中的引用，密钥不会因查看而进入保存请求或审计记录。来源管理凭据保留在服务端，所有设置接口要求来源管理员权限。普通临时控制权限不能用于高级配置。需要在来源设置启用「保留临时配置」后才能保存，持久化失败时不会提示已确认保存。

设置先写入控制台加密的待应用记录，再由网关做版本检查、原生编译和原子切换，随后保存恢复快照。请求超时会显示待确认，可从操作记录核对；不会自动重放旧操作覆盖新配置。新请求使用新快照，在途请求保留旧快照。

恢复基础值会去掉对应设置覆盖；未显式配置的字段按网关继承规则执行。0、false 和删除字段区分处理。`timeout_policy` 的有效结果由网关计算。请求预览复用原生协议转换/参数覆盖代码，不发送模型请求；模型发现只在点击按钮时请求上游模型列表。

API key 的跨渠道调度/权重/重试预算，以及全局 hedging，仍属于各自原有作用范围。`smart_round_robin` 在当前原生运行时实际按轮询执行，因此不作为成功率调度选项。

## 接口与恢复格式

网关：

- `GET /v1/channel-settings/schema`
- `GET /v1/channel-settings?provider=...`
- `GET /v1/channel-settings/secrets?provider=...&revision=...`：显式管理员按需读取单渠道 API key，检查编辑版本，禁止缓存。
- `POST /v1/channel-settings/validate`
- `POST /v1/channel-settings/discover`
- `PATCH /v1/channel-settings`
- `GET /v1/channel-settings/operations/{id}`
- `GET /v1/channel-settings/export`、`providers`：仅来源管理员/控制台后端使用，不转发给浏览器。

控制台代理入口为 `/v1/sources/{id}/channel-settings`，另提供 `/operations`、`/rollback` 及 `/v1/channel-setting-templates`。回滚以新的带 revision 的操作应用，保留操作记录。跨来源分别提交，不承诺分布式原子应用。

恢复快照 v2 增加 `channel_settings` 和临时渠道完整 `definition`；新网关兼容 v1/v2。来源启动恢复会声明 `X-Uni-Channel-Settings-Version: 1`；不支持的旧网关无法读取 v2，控制台保留已知良好快照，不清除高级设置。发布顺序为先网关，再控制台。
