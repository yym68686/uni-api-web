# 完整配置托管

托管按来源启用。现有来源可在「来源设置 → 完整配置托管」中从兼容的
在线网关导入草稿。导入一次读取基础配置和运行时规则，避免把两个
不同版本拼在一起。新来源尚未上线时，可勾选「预登记尚未上线的托管来源」，
使用该来源的管理员密钥登记；再手动保存完整 YAML 或 JSON 草稿。

「校验并发布」把草稿交给启用托管的网关。只有网关校验 API key、渠道、
规则引用并确认成功后才发布；校验失败不会覆盖已发布版本。单独导入或
保存草稿不修改业务实例。已发布不等于已切流：控制台单独查询稳定
业务入口的已应用版本。请在 Fugue 再验证真实业务请求。

网关环境变量 `UNI_API_MANAGED_CONFIG_URL` 指向 analytics 的私有
`/v1/runtime-config/<source-id>`。 `UNI_API_MANAGED_CONFIG_ADMIN_KEY`
复用同一来源的配置管理员密钥：有配置读取管理员密钥时使用该值；
否则使用平台密钥（它必须是网关中的管理员密钥）。密钥不放进 URL、
Git 或日志。初次配置时，草稿也必须包含该管理员 key 和它的管理员角色。
托管文档是完整、可直接运行的配置；不要从中引用网关的进程环境变量。

草稿与发布版本加密存入 PostgreSQL，保留当前版本、当前草稿和最近
20 个版本。浏览器只接收状态和版本号，不会从服务器取回明文配置。
正在运行的网关会继续使用已验证版本，旧的临时配置同步器不会覆盖
托管状态。配置托管不复制网关的业务数据库、本地 spool 或其他文件。
